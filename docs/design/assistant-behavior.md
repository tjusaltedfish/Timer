# 助手、时间边界与跨端反馈

日期：2026-10-19。适用源码版本：1.1.0+3。本文描述本轮已实现规则及仍需实机验证的范围；源码完成不等于运行中的旧版已更新。

## 1. 助手身份与表达

Timer 是单人使用的执行助手：直接、平静、可靠。先给出能执行的安排，必要时只问一个关键问题；通常两句话以内，不展示 t1/b1 等模型内部引用，不把估时当作拒绝安排的硬条件，不擅自降低验收标准。

用户说“今天 12 点前完成这个项目”，如果任务指代明确，就尽量给出截止前的可用窗口。安排结束仍要用户反馈，不能据此承诺完成。若目标时刻已过，需要明确补记还是重新安排，不能偷偷改成明天。

**直接执行（2026-10-20 起默认）。** 用户反馈“它不干活、说一大堆”，因此助手不再停在拟办：模型给出的改动先经领域规则预检，通过后立即执行，回复只用一句完成时说明做了什么；同一条消息下的卡片列出实际改动，并提供「撤销」（公众号回复「撤销」或「撤销 编号」）。撤销按执行前后快照反推操作（新建→撤下、改期→改回、撤下→恢复、整件不做→重新打开），并按版本整体执行；之后若又改过同一对象，撤销会被拒绝而不是部分回滚。涉及执行、反馈和等待结果的改动不提供撤销。设置「改动前先问我」打开时回到拟办＋确认模式。预检或执行失败时绝不沿用模型“已排好”的说法，只说明没办成的原因；改动已经发生时，模型回复里的追问句（“你定？”）会被去掉。

可用动作新增 `cancel_block`（撤下单段，含没有待办的保护时段，如“把明早的吃饭关了”）、`cancel_task`（整件事不做）和带 `minutes` 的 `move_block`（改期同时改时长；用户点名的固定/保护时段允许移动）。领域层相应新增 `block.cancel` / `block.restore`，App 的时间段详情也提供“删除这一段 / 只撤下这一段”。

实测（2026-10-20，官方 DeepSeek，隔离临时库）：“今天上午12点之前完成这个项目的开发”→ 直接排 11:10–12:00 并说明还差约 10 分钟；“把吃饭2改到下午一点”“续接两小时 fab 曝光测试”“把明天早上的吃饭关了”均一句话办成；“我上午脑子最清楚，实验放上午”被存为长期偏好。App 的操作按钮及公众号明确的“完成了 / 再给我15分钟 / 今日总结：… / 记住：…”是直接用户指令，不需要模型先自行决定是否执行。

## 2. 时间处理矩阵

| 情况 | 处理方式 | 保留的边界 |
|---|---|---|
| 新建未来安排 | 按设置时区解析，检查冲突、固定/保护、依赖和截止 | 不占用当前执行续时后的预计时间 |
| 用户说“现在/马上” | 使用显式 now 语义，确认时重新取当前时刻 | 拟办 15 分钟失效；有结束上限时仍守上限 |
| 模型回“11:10”，实际 11:10:35 | 当前分钟可归一到当前时刻之后；模型耗时导致跨分钟时最多补偿 2 分钟 | 只处理请求当时的分钟，不普遍放行过去时间 |
| 给定“12 点之前” | 保存 until_at，限制真实结束时刻；截断可用时长而非修改已有任务剩余量 | 小于 5 分钟需重新安排；完成状态仍待反馈 |
| 普通绝对时间已过 | 拒绝作为未来安排，提示明确补记或另排 | 不自动滚到次日、不改执行历史 |
| 已过时且没有开始记录 | App 提供“补记这一段的结果”和“这段没有开始”；公众号在刚过时后询问实际情况 | 补记属于用户报告，不伪造计时区间 |
| 当前正在投入 | 专注面板显示任务、倒计时、预计收尾、暂停/结束/续时 | 同一时间仅一段 running/paused |
| 暂停后恢复、迟到或续时 | 真实事件保存，后续按原有确定性规则微调或给出提案 | 固定/保护、既有执行记录、跨日与截止边界保留 |
| 时间到了但未反馈 | 提问结果，或允许计时结束后 30 分钟内续时 | 不自动完成；空档不算实际投入 |
| 用户“还差半小时” | 区分剩余工作量、当前续时和未来改期；含糊时只问一句 | 不把这三种修改混为一谈 |
| 等待外部结果 | 释放个人投入；以同一个检查点改约，保留版本校验 | 等待时间不计作实际投入，不算完成 |
| 确认前任务、安排或执行已变化 | 检验对象版本，拒绝过期拟办并重新生成 | 不覆盖手机/电脑已经做出的新修改 |
| 夏令时不存在/重复时刻 | 不存在则拒绝；重复则明确第一次/第二次并提供偏移 | 不擅自挑一次重复时刻 |
| 删除待办 | 用 cancelled 撤下未来安排、关闭待反馈段并停止检查点 | active 段先结束；既有计时和反馈保留，可从历史重新打开 |

新建表单默认严格取当前时刻之后，包含“恰好整分钟打开”的情况。日界、周界、日终时间均使用用户设置时区；示例 America/Los_Angeles 不代替真实作息设置。

## 3. 记忆的来源与删除

| 层次 | 已实现的来源 | 使用规则 |
|---|---|---|
| 长期偏好 | 助手页“记忆”手动新增/删除，或公众号/对话“记住：…”“忘记：…” | 最多 50 条，每条 1000 字；只保存用户明确提供的内容，写入操作日志 |
| 当前事实 | 任务、时间块、执行、等待检查点 | 每次从权威快照构造，不依赖模型记忆推断是否完成 |
| 近期上下文 | 最近对话、3 条原文回顾、8 份材料摘要/说明、2 份 AI 复盘 | 有界读取，标明原文与生成内容；不是完整历史全文检索 |
| 学习材料 | 用户选择的文件、说明、提取文字与带位置的摘要 | 仅在生成复盘时按用户选项发原文；原始文件留电脑 |

删除偏好后不再放入偏好上下文，原先的“记住/忘记”命令也从模型的近期聊天上下文中排除。删除不等于清除不可变操作审计或历史对话记录。

除“记住：…”外，模型可以在用户**亲口说出**自己的长期习惯或偏好时，在回复的 `remember` 字段写一句（每次最多 3 条），系统保存为来源“助手”的记忆并在回复末尾写明“已记下：…”；它们与手动记忆一样出现在“记忆”列表，可随时删除，重复内容不再保存。一次性安排、情绪和闲聊不记。

本轮没有向量检索、自动提取人格画像或间隔复习卡片。材料复盘结果会进入近期助手上下文，但不会自动变成用户确认的长期偏好。

## 4. 公众号主动消息与回复

通道仍采用 Claude 已接通的公众号测试号及原有持久 outbox。调度在电脑后台进行，App 窗口关闭后仍可运行；电脑服务与网络需要在线。升级时从当前事件水位开始，不重发全部历史编辑。

| 触发 | 模板内容 | 时效/去重 |
|---|---|---|
| 手机/电脑新增待办及安排 | “待办已添加 / 任务 / 目标 / 安排时段” | 同一轮合并建任务与建时间块；只处理新事件 |
| 点击开始 | “已进入专注 / 任务 / 预计几点收尾” | 真实开始成功后发送；不由计划到点推定开始 |
| 到开始时刻但没开始 | “该开始了 / 任务 / 打开 Timer 开始” | 开始后撤下尚未发送的提示 |
| 未开始且时段刚过 | “时间已过 / 实际做了、没开始还是重新安排？” | 不伪造投入，不补发整批陈旧提醒 |
| 执行到点 | “这一段到时间了 / 完成了 编号 / 再给我15分钟 编号” | 六位编号绑定执行段；续时或反馈后旧追问失效 |
| 等待检查点到时 | “看看等待的结果 / 任务 / 回来了吗？” | 改约/解决/删除后旧检查提示失效 |
| 日终时间 | 确定性收尾摘要、未确认数、两三句输入提示 | 按本地日期去重；无原文时先询问 |
| AI 复盘生成完成 | 复盘摘要及“完整出处见回顾页” | 独立作业结果通知，全文存电脑 |

到点追问的模板为“这一段到时间了 / 做完了吗？· 完成了 · 再给我15分钟 · 要推迟就直接说（如“剩下的推到晚上八点”）”，只有一个进行中的段时不再附编号。公众号里由助手完成的改动只回一次（不再额外推送“待办已添加”回执）。

回复规则：只有一个可处理执行段时可不带编号；多个执行段时需明确编号/任务。续时与完成命令用入站 ID 生成幂等操作 ID。点击发送成功、微信接口成功、用户已读/任务已完成是不同状态。

客服消息超出互动窗口时仍依赖已配置的模板 ID（测试号模板字段沿用 `{{content.DATA}}`）；未配置或接口拒绝会保留 failed/unknown 等可见状态，不承诺任意时间无限主动推送。发送前复查问询版本和业务状态；网络超时后送达未知时不盲目重发。

设置页“微信助手”可关闭主动推送。实际公众号投递、模板额度与 48 小时外行为须在激活新版后验收；本轮消息测试使用模拟微信服务器。

## 5. 文件与文字复盘

回顾页流程：添加材料 → 写两三句话 → 生成复盘，或先保存文字，等日终自动生成。支持手机与电脑手动选文件；既有文件/目录不会自动扫描。

- 文件类型：文本 PDF、DOCX、Markdown、TXT、CSV、JSON、文本代码/日志。每份最多 8 MB、60000 字；PDF 最多 100 页，每天最多 10 份材料。扫描件/图片 OCR 尚不支持。
- 位置来源：PDF 页码、DOCX 段落/表格、文本行区间；保存原文件 SHA-256。模型被要求保留出处，结论仍应与原文核对。
- 上传时可取消“把提取文字发送给模型”，此时只使用用户填写的说明。每份原文/提取文字保存在电脑数据目录的 materials 中，快照不下发全文。
- 先保存原文，再调用模型。每份允许外发的材料生成一次摘要并复用；然后结合当天记录和原文生成复盘。失败保留输入；同一请求重试不重复写回顾版本或生成完成结果。
- 收尾时自动生成开关默认打开。已有当天原文时才生成；没有原文时先问。自动失败最多两次、间隔至少 15 分钟，且受每日调用上限约束，不无限重试。
- AI 复盘与用户原文分开保存，记录模型、生成时间、材料与指纹，进入 Markdown/JSON 归档。计划、真实计时、等待和用户报告分别统计，旧安排标为已调整/撤下。

“不外发目录”管理、完整长文检索、回忆卡片与间隔复习仍按 daily-review.md 后续阶段推进；不把本轮材料摘要等同于这些能力已完成。

## 6. 手机通知

现有 Android 通知驱动和清单权限继续使用。首页在提醒未启用时给出入口；设置页可申请权限、允许准时提醒，并安排 15 秒后的系统通知测试，便于切后台/锁屏观察。续时、改约、删除会重建或撤销旧提醒。

本地通知针对已同步到手机的状态；手机离线时不会自动获得电脑后来新建的安排。公众号服务端推送与手机本地通知互为补充。系统强停、ColorOS 后台、省电和通知展示需要 OPPO 真机验证；本轮没有连接 ADB 设备，不能把构建成功或驱动替身测试记成真机通过。

## 7. 发布与验证

源码测试、隔离原生流程和生产激活分别记录在 STATUS.md。准备包版本 1.1.0+3。开发宿主的 AppData 会发生重定向，激活前须确保使用当前正式数据环境；普通终端可用已准备产物执行：

```powershell
cd C:\Users\ASUS\Documents\Timer
.\tools\release.ps1 -Prepared -ValidateOnly
# 关闭正在运行的 Timer 窗口后：
.\tools\release.ps1 -Prepared
```

Prepared 只使用已经构建且校验和匹配的客户端，不再次递增版本或重新编译。它安装电脑客户端、把 APK 发布到正常数据目录并重启后台。设备配对与用户数据沿用原位置。
